# 社区养老服务平台 · 服务器部署文档

> 本文档记录**已在云服务器上实际完成**的部署过程与最终状态（4 个容器全部 Up、`api` 为 healthy、`env=prod`）。

## 0. 占位符说明

文档中所有敏感值都以占位符出现，阅读时按下表替换成自己的真实值即可（替换后不要提交到仓库）。

| 占位符 | 含义 | 填写方式 |
| --- | --- | --- |
| `<SERVER_IP>` | 服务器公网地址 | 控制台里看到的公网 IP 或已解析的域名 |
| `<SSH_USER>` | 服务器登录用户 | 具备 docker 执行权限的普通用户（如 `ubuntu`） |
| `<REPO_URL>` | 代码仓库地址 | `git@github.com:<owner>/<repo>.git`（推荐 SSH） |
| `<POSTGRES_PASSWORD>` | 既有 PostgreSQL 的密码 | 从 `pg` 容器的 `POSTGRES_PASSWORD` 环境变量读取；**必须只含 `0-9a-f`** |
| `<JWT_SECRET>` | 登录令牌签名密钥 | `openssl rand -hex 32`（64 位 hex，≥32 字节） |
| `<MINIO_ACCESS_KEY>` | 既有 MinIO 的 AccessKey | 从 MinIO 服务的环境变量读取（`/etc/default/minio` 或进程环境） |
| `<MINIO_SECRET_KEY>` | 既有 MinIO 的 SecretKey | 同上 |
| `<MINIO_PUBLIC_BASE_URL>` | 图片直链前缀（浏览器可达） | `http://<SERVER_IP>:9000/<BUCKET>` |
| `<BUCKET>` | MinIO 桶名 | 默认 `socialoldcare-media`，与 `MINIO_BUCKET` 一致 |
| `<ADMIN_PHONE>` | 管理员登录手机号 | 自定义，登录后台用的账号 |
| `<DOMAIN>` | 域名（启用 HTTPS 时才需要） | 已备案并解析到 `<SERVER_IP>` 的域名 |

> `deploy/.env.example`、`deploy/docker-compose.yml`、`deploy/nginx/*.conf` 中的默认值同样只是示例，
> 运行时以服务器上的 `deploy/.env` 为准；`.env` 已被 `.gitignore` 排除，不要提交。

## 2. 子项目与构建产物

| 子项目 | 技术栈 | 构建方式 | 产物 / 运行形态 | 运行时依赖 |
| --- | --- | --- | --- | --- |
| `apps/api` | FastAPI + SQLAlchemy 2 + Alembic | `deploy/Dockerfile.api`：`pip install -r deploy/requirements.txt` | 无打包产物，源码 + `migrations/`、`sql/`、`scripts/` 一起进镜像 | Python 3.12、PostgreSQL、MinIO |
| `apps/admin` | Vue3 + Vite 6 + TS | `deploy/Dockerfile.admin`：`pnpm build`（`base=/`） | `dist/` → 容器内 nginx 托管 | 无（纯静态） |
| `apps/h5` | Vue3 + Vite 6 + TS | `deploy/Dockerfile.h5`：`pnpm build`（`base=/h5/`） | `dist/` → 容器内 nginx 托管 | 无（纯静态） |
| `apps/miniapp` | 微信小程序原生 | 微信开发者工具上传 | — | 本次不部署 |

调用关系：admin / h5 的请求基址固定为 `/api/v1`（与后端同源，浏览器不触发跨域）；api 读写 PostgreSQL，上传/读取对象存储走 MinIO；小程序（未部署）直连 `http://<SERVER_IP>`。

三个 Dockerfile 的构建上下文都是**仓库根目录**（compose 里 `context: ..`），因为要读 `../apps/**`。这也意味着：**服务器上必须有完整仓库，不能只拷 `deploy/` 目录**。根目录 `.dockerignore` 负责把 `node_modules/`、`dist/`、`.venv/`、`.git/`、`.env*` 挡在构建上下文之外。

## 3. 端口与路由

宿主端口占用：

| 端口 | 使用者 | 说明 |
| --- | --- | --- |
| `80` | `socialoldcare-nginx` | 唯一对公网开放的业务端口 |
| `127.0.0.1:8000` | `socialoldcare-api` | 只绑回环，用于服务器本机排错，公网不可达 |
| `127.0.0.1:5432` | `pg` | 既有数据库，保持不变 |
| `9000` | MinIO（宿主机进程） | 既有对象存储，保持不变 |

入口网关（`deploy/nginx/default.conf`）路由：

| location | 转发目标 | 要点 |
| --- | --- | --- |
| `/api/` | `http://api:8000` | `proxy_pass` **不带 URI 结尾**，保留 `/api/v1` 前缀 |
| `= /healthz` | `http://api:8000/healthz` | 健康检查，关闭 access_log |
| `= /api` | `return 404` | 防止漏写斜杠时落到后台静态站返回 200 HTML |
| `/h5/` | `http://h5:80/` | 末尾 `/` 削掉 `/h5` 前缀；h5 容器按站点根目录托管 |
| `= /h5` | `301 /h5/` | 补全斜杠，否则前端路由 base 判定会错 |
| `/` | `http://admin:80` | 管理后台 |
| `/docs`、`/redoc`、`/openapi.json` | **默认注释关闭** | 见第 12 节 |

两个静态站容器（`nginx/admin.conf`、`nginx/h5.conf`）只做静态托管 + SPA 兜底，**不反代 `/api`**：接口统一由网关分流，重启 api 不会连带静态站启动失败。缓存策略只有一条 `add_header Cache-Control`（`/assets/` 长缓存、`index.html` `no-cache`），不要再叠加 `expires`，否则响应里会出现两个 `Cache-Control`。

## 4. 环境变量说明

`deploy/.env` 是唯一一份部署变量（后端业务默认值仍由 `apps/api/app/core/config.py` 提供）。compose 用 `env_file` 打底，再用 `environment` 覆盖并拼出 `DATABASE_URL`。

| 变量 | 必填 | 取值要求 |
| --- | --- | --- |
| `POSTGRES_DB` / `POSTGRES_USER` | 是 | 与既有 `pg` 容器一致（默认 `socialoldcare`） |
| `POSTGRES_PASSWORD` | 是 | 既有库的真实密码；**只允许 `0-9a-f`**，含 `@ : / #` 会截断 `DATABASE_URL` |
| `POSTGRES_HOST` | 是 | 固定 `postgres`（指向网络别名，不是容器实名 `pg`） |
| `APP_ENV` | 是 | `prod`：启动时强制校验下面三项 |
| `JWT_SECRET` | 是 | `openssl rand -hex 32`；不足 32 字节会**启动失败**（占位符只有 32 位，正好被拦下） |
| `ALLOW_DEMO_LOGIN` | 是 | `prod` 下必须 `false` |
| `AUTO_SEED` | 是 | `prod` 下必须 `false`（不预置业务数据） |
| `AUTO_MIGRATE` | 否 | 默认 `true`：启动时 `alembic upgrade head`，已是最新则静默跳过 |
| `CORS_ORIGINS` | 否 | 同域部署下不触发；填 `http://<SERVER_IP>` 便于排查 |
| `STORAGE_PROVIDER` | 是 | `minio` |
| `MINIO_ENDPOINT` | 是 | 宿主机进程 → `host.docker.internal:9000`；若 MinIO 是容器 → `minio:9000`（需接入网络并起别名） |
| `MINIO_BUCKET` | 是 | `socialoldcare-media`（`init_minio.py` 会按此建桶） |
| `MINIO_SECURE` | 否 | `false`：当前 MinIO 是 HTTP；启用 HTTPS 后改 `true` |
| `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY` | 是 | 既有 MinIO 的凭据；**不要用默认的 `minioadmin`** |
| `MINIO_PUBLIC_BASE_URL` | 是 | `http://<SERVER_IP>:9000/<BUCKET>`，必须是**浏览器可达**地址，写 `minio:9000` 会 302 到浏览器解析不了的主机 |
| `FILE_DELIVERY` | 否 | `redirect`：302 到对象存储直链，图片流量不过 api |
| `REQUIRE_FILE_AUTH` | 否 | 移动端 `<img src>` 直连图片时必须 `false` |

改完 `.env` 做三项自查：

```bash
cd /opt/socialoldcare/deploy
grep -c 'CHANGE_ME' .env                  # 期望 0
docker compose config -q && echo CONFIG_OK
docker compose config | grep -E 'DATABASE_URL|MINIO_ENDPOINT|MINIO_PUBLIC_BASE_URL'
```

`DATABASE_URL` 应渲染成 `postgresql+psycopg://socialoldcare:<POSTGRES_PASSWORD>@postgres:5432/socialoldcare`。

## 5. 部署步骤

### 5.1 前置检查

```bash
docker --version && docker compose version        # compose 建议 ≥ 2.20
ss -ltnp | grep -E ':80 |:8000 '                  # 80 必须空闲
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
df -h / | tail -1                                 # 构建需要 ≥3G 空闲
```

记录两件事：`pg` 容器的名字、MinIO 是容器还是宿主机进程（`docker ps` 看不到 9000 但 `ss` 有 → 宿主机进程）。

### 5.2 获取代码

国内服务器直连 GitHub 的 22 端口常被卡住，用 **SSH over 443**：

```bash
ssh-keygen -t ed25519 -C "deploy-key" -f ~/.ssh/id_ed25519 -N ""
cat ~/.ssh/id_ed25519.pub          # 复制到仓库 Settings → Deploy keys（只读即可）

cat >> ~/.ssh/config <<'EOF'
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile ~/.ssh/id_ed25519
  StrictHostKeyChecking accept-new
EOF
chmod 600 ~/.ssh/config

ssh -T git@github.com              # 出现 successfully authenticated 即可
```

```bash
sudo mkdir -p /opt/socialoldcare
sudo chown -R "<SSH_USER>":"<SSH_USER>" /opt/socialoldcare
git clone <REPO_URL> /opt/socialoldcare
cd /opt/socialoldcare && git log --oneline -1 && ls deploy
```

要点：`git clone` 允许目标目录已存在（但必须为空）；`chown` 不能创建目录，顺序是 `mkdir` → `chown` → `clone`。

### 5.3 共享网络与既有数据库接入

```bash
# 1) 建共享网络（已存在会报错，忽略）
docker network create socialoldcare-net

# 2) 把既有 PG 接入并起别名 postgres（.env 里 POSTGRES_HOST=postgres 指向它）
docker network connect --alias postgres socialoldcare-net pg

# 3) 验证
docker exec pg getent hosts postgres                 # 期望 172.x.x.x  postgres
docker network inspect socialoldcare-net --format '{{range .Containers}}{{.Name}} {{end}}'
```

- 重复执行会报 `already exists` / `already connected`，忽略；
- 网络连接随容器重启保留，但 **`pg` 容器被删除重建后别名会丢**，需重连一次；
- MinIO 是宿主机进程，**不需要**接入网络；若将来改成容器，再 `docker network connect --alias minio ...` 并把 `MINIO_ENDPOINT` 改成 `minio:9000`。

### 5.4 填写 `.env`

```bash
cd /opt/socialoldcare/deploy
cp -n .env.example .env
chmod 600 .env
openssl rand -hex 32                # 生成 <JWT_SECRET>
```

逐项替换 `POSTGRES_PASSWORD`、`JWT_SECRET`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_ENDPOINT`、`MINIO_PUBLIC_BASE_URL`，然后跑第 4 节的三项自查。

### 5.5 构建镜像

```bash
cd /opt/socialoldcare/deploy
docker compose build api        # 首次 2~4 分钟
docker compose build admin h5   # 各 1~2 分钟
```

国内网络相关默认值（已写在 Dockerfile 里，无需手工改）：

| 构建环节 | 默认值 | 覆盖方式 |
| --- | --- | --- |
| Debian apt（装 `tzdata`） | `mirrors.cloud.tencent.com` | `--build-arg APT_MIRROR=mirrors.tuna.tsinghua.edu.cn` |
| PyPI | `pypi.tuna.tsinghua.edu.cn` | `--build-arg PIP_INDEX_URL=https://pypi.org/simple` |
| npm / pnpm | `registry.npmmirror.com` | `--build-arg NPM_REGISTRY=https://registry.npmjs.org` |

成功标志：`naming to docker.io/library/socialoldcare/api:0.2.0`（admin/h5 同理）。

### 5.6 启动与自检

```bash
docker compose up -d
docker compose ps                    # api 从 Up 变 Up (healthy) 约需 20~60s
docker compose logs --tail=100 api   # 期望 Uvicorn running on http://0.0.0.0:8000
docker compose exec nginx nginx -t   # syntax is ok / test is successful
```

### 6.1 当前数据库状态

部署时数据库中**已有业务数据**，且迁移版本已是 head：

| 检查项 | 实际结果 | 含义 |
| --- | --- | --- |
| `alembic_version` | `c4aec9c0e272`（= 代码 head） | 启动时 `AUTO_MIGRATE` 比对后**不执行任何迁移** |
| `public` 表数量 | 17（与 `app/db/models.py` 的 17 个模型一致） | 表结构无需重建 |
| `uq_stations_name` 约束 | 已存在 | 迁移 `c4aec9c0e272` 已应用过 |

只读确认命令（不会修改任何数据）：

```bash
docker compose exec api alembic current
docker exec pg psql -U socialoldcare -d socialoldcare -Atc "select version_num from alembic_version"
docker exec pg psql -U socialoldcare -d socialoldcare -Atc "select count(*) from information_schema.tables where table_schema='public'"
```

### 6.2 不要执行的命令

| 命令 | 为什么不要执行 |
| --- | --- |
| `python scripts/apply_sql.py` | 只在**空库首次部署**时需要（站点/账号/老人/服务项目）。已有数据时它会按 name/phone 判重插入，并在文件末尾 `UPDATE users SET password_hash=...`，把家属/工作人员密码重置为初始值 |
| `alembic stamp ...` | 仅当 `alembic_version` 缺失或落后时才用。当前已是 head，`stamp` 属于多余操作 |
| `drop schema public cascade` 之类清库语句 | 会连同业务数据一起删除，除非明确要重建 |

### 6.3 幂等脚本：先确认，再决定跑不跑

| 脚本 | 作用 | 是否已存在（只读确认） | 已存在时 |
| --- | --- | --- | --- |
| `scripts/init_minio.py` | 建桶 + 设置匿名只读策略（仅 `s3:GetObject`） | 见下方 Python 片段 | 可跳过；跑也无害（`[skip]` 后重新设置策略） |
| `scripts/create_admin.py` | 创建/重置管理员 | `select id, phone, name, role, status from users where role='admin'` | 有输出即可跳过；要改密码才加 `--reset` |

MinIO 桶与策略的只读确认：

```bash
docker compose exec -T api python -c "
from app.core.config import settings
from minio import Minio
from minio.error import S3Error
c = Minio(settings.minio_endpoint, settings.minio_access_key, settings.minio_secret_key, secure=settings.minio_secure)
print('bucket_exists:', c.bucket_exists(settings.minio_bucket))
try:
    print('anon_read_ok:', 's3:GetObject' in c.get_bucket_policy(settings.minio_bucket))
except S3Error as e:
    print('anon_read_ok: False ->', e.code)
"
```

只有当桶不存在或 `anon_read_ok: False` 时才执行 `docker compose exec api python scripts/init_minio.py`；管理员同理，缺了才执行：

```bash
docker compose exec api python scripts/create_admin.py --phone <ADMIN_PHONE> --name 管理员
```

### 6.4 升级前备份

```bash
mkdir -p ~/backup
docker exec pg pg_dump -U socialoldcare socialoldcare | gzip > ~/backup/db-<DATE>.sql.gz
ls -lh ~/backup/
```

## 7. 验收清单

服务器本机（四条，全部要通过）：

```bash
curl -s http://127.0.0.1/healthz; echo
# {"ok":true,"env":"prod"}

curl -s -o /dev/null -w 'admin %{http_code}\n' http://127.0.0.1/
# admin 200

curl -s -o /dev/null -w 'h5    %{http_code}\n' http://127.0.0.1/h5/
# h5    200

curl -s http://127.0.0.1/api/v1/__ping; echo
# {"detail":"Not Found"}  ← 返回 JSON 说明请求真的到了 FastAPI
```

最后一条若返回 HTML，说明 `/api/` 落到了后台静态站，检查 `docker compose exec nginx nginx -t` 与 `location /api/` 的 `proxy_pass`。

公网验收（安全组放行 TCP `80` 后）：

1. `http://<SERVER_IP>/` → 后台登录页，用管理员账号登录；
2. `http://<SERVER_IP>/h5/` → H5 首页，进入内页后**刷新**不能 404（SPA 兜底）；
3. 后台上传一张图片 → 返回的 `<MINIO_PUBLIC_BASE_URL>/<key>` 直链能直接打开（能打开说明桶策略与公网前缀都正确）；
4. `docker compose ps` 四个容器均为 `Up`，`api` 为 `healthy`，无反复重启。

## 8. 日常更新流程

服务器上的 `/opt/socialoldcare` 是真 git 仓库，更新 = 拉代码 → 重建受影响的服务 → 替换容器。**不需要**重跑初始化脚本，也不会动数据库。

```bash
cd /opt/socialoldcare && git pull
cd deploy
docker compose build <服务名>
docker compose up -d
docker compose ps && docker compose logs --tail=50 api
```

| 改动内容 | 要执行的操作 | 大约耗时 |
| --- | --- | --- |
| 后端 `apps/api/app/**` | `build api` → `up -d api` | 1~2 min |
| 新增/修改迁移 `migrations/versions/*` | 同上；`AUTO_MIGRATE=true` 时启动自动 `upgrade head` | +几秒 |
| 管理后台 `apps/admin/**` | `build admin` → `up -d admin` | 1~2 min |
| H5 `apps/h5/**` | `build h5` → `up -d h5` | 1~2 min |
| 前端依赖（`package.json` / `pnpm-lock.yaml`） | 同上，`pnpm install` 层自动失效重装 | 2~3 min |
| 后端依赖（`pyproject.toml` / `uv.lock`） | **本机**重新导出 `deploy/requirements.txt` 并提交，再 `build api` | 2~3 min |
| `deploy/nginx/*.conf` | `docker compose run --rm nginx nginx -t` 校验后 `docker compose restart nginx`（**不用 build**） | 秒级 |
| `deploy/.env` | `docker compose up -d --force-recreate api`（环境变量只在创建容器时注入） | 秒级 |
| 全量 | `docker compose build && docker compose up -d` | 5~8 min |

后端依赖变更时，在本机 `apps/api` 下重新导出：

```bash
uv lock
uv export --frozen --no-dev --no-hashes --no-annotate --no-header \
  --format requirements-txt -o ../../deploy/requirements.txt
```

有迁移的更新，先做第 6.4 节的备份；回滚代码时若迁移也要退，用 `docker compose exec api alembic downgrade -1`。

`up -d` 会销毁旧容器再起新的，单机部署有几秒不可用（静态站几乎无感，api 断 1~2 秒）。

## 9. 运维注意点（现象 → 原因 → 处理）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker compose build api` 停在 `apt-get update`，速度只有几 KB/s，十几分钟不动 | 基础镜像走 Debian 官方源 `deb.debian.org`，国内极慢 | Dockerfile 已默认把源换成 `mirrors.cloud.tencent.com`（`ARG APT_MIRROR` 可覆盖）；老版本镜像需 `git pull` 后重建 |
| `git clone` 卡在 `Cloning into ...` 无进度 | 服务器到 GitHub 的 22/443 出口被拖死 | 用 SSH over 443：`~/.ssh/config` 把 `github.com` 指向 `ssh.github.com:443`，见 5.2 |
| `fatal: Unable to read current working directory` | 终端所在目录被 `rm -rf` 删掉了（幽灵目录） | 先 `cd ~` 再执行 git；删目录前务必离开它 |
| `chown: cannot access ...: No such file or directory` | `chown` 不能创建目录 | 顺序固定：`mkdir -p` → `chown` → `clone` |
| 改了后端代码，`git pull` + `restart` 却不生效 | 代码是通过 `COPY` 进镜像的，镜像不可变 | 必须 `docker compose build api` 再 `up -d api` |
| 改了 nginx 配置，`build` 了却没生效 | 配置是 `volumes` 只读挂载，与镜像无关 | 校验后 `docker compose restart nginx`（或用 `nginx -s reload`）即可，无需 build |
| 图片 302 到 `minio:9000` 打不开 | `MINIO_PUBLIC_BASE_URL` 写成了容器内网名 | 改成 `http://<SERVER_IP>:9000/<BUCKET>`（浏览器可达） |
| api 日志 `could not translate host name "postgres"` | `pg` 没接入共享网络，或容器被重建导致别名丢失 | 重跑 `docker network connect --alias postgres socialoldcare-net pg` |
| api 连 MinIO 超时 | `MINIO_ENDPOINT` 填了 `127.0.0.1:9000`（容器内的 127.0.0.1 是它自己） | 宿主机进程用 `host.docker.internal:9000`，并确认 MinIO 监听 `0.0.0.0` |
| 重启 api 时静态站也 502 | 静态站容器里又配了 `/api` 反代，启动时解析不到 `api` 主机 | 静态站只管静态文件，接口统一由入口网关分流 |
| `/api/v1/__ping` 返回 200 HTML | `/api/` 没匹配到，落到了后台 SPA | 检查 `location /api/` 是否存在、`proxy_pass` 结尾不能带 URI |
| `/h5/` 白屏、`/h5/assets/*` 404 | h5 构建 `base` 不是 `/h5/`，或网关 `proxy_pass http://h5:80/` 末尾少了 `/` | 确认生产模式构建；网关末尾必须带 `/` |
| 磁盘被镜像占满 | 每次 build 都留旧层 | `docker image prune -f`、`docker builder prune -f --filter until=168h` |

## 12. API 文档（`/docs`）策略

FastAPI 默认会暴露 `/docs`、`/redoc`、`/openapi.json`。当前状态：

- 入口网关里这三个 `location` 是**注释关闭**的，公网访问 `/docs` 实际落到 `location /` → 返回后台的 `index.html`，不是 Swagger；
- api 只绑定 `127.0.0.1:8000`，公网无法直连 8000。

**不建议对公网开放**：`/openapi.json` 包含完整接口清单、字段类型、枚举值与必填项，等于把系统结构交给扫描器；虽然后端有 JWT 鉴权，但泄露的是攻击面信息。

本地查看的两种方式：

```bash
# 方式一：SSH 隧道（推荐，看完即断）
ssh -N -L 18000:127.0.0.1:8000 <SSH_USER>@<SERVER_IP>
# 浏览器打开 http://127.0.0.1:18000/docs

# 方式二：导出 schema 后导入 Apifox / Postman
curl -s http://127.0.0.1:8000/openapi.json -o ~/openapi.json
```

确实需要临时开放时，取消 `deploy/nginx/default.conf` 中两行注释，并加来源限制：

```nginx
location /docs {
    allow <YOUR_IP>;   # 只允许自己的出口 IP
    deny  all;
    proxy_pass http://api:8000;
}
location /openapi.json {
    allow <YOUR_IP>;
    deny  all;
    proxy_pass http://api:8000;
}
```

改完 `docker compose run --rm nginx nginx -t` 校验，再 `docker compose restart nginx`。
