# 社区养老服务平台 · 部署架构说明

> **可执行步骤全部在 [`deploy/README.md`](../deploy/README.md)**（部署唯一入口）。
> 本文只说明「为什么这么部署」：拓扑、镜像构成、路由规则、变量约束与踩坑点。

目标机：`120.53.13.162`。服务器上已有 PostgreSQL（容器 `pg`，`127.0.0.1:5432`）、MinIO（`9000`）、MongoDB（`27017`，与本项目无关）。
本项目只做增量：新增 4 个容器，复用已有 PG / MinIO，不重建它们的容器与数据卷。

## 2. 镜像构成要点

### 2.1 后端为什么用 pip 而不是 uv

原 `apps/api/Dockerfile` 依赖 `ghcr.io/astral-sh/uv` 镜像，国内服务器拉取经常失败；部署版改为 `python:3.12-slim` + `pip install -r requirements.txt`：

- `deploy/requirements.txt` 由 `apps/api/uv.lock` 导出，**版本全锁定**（不含 pytest/ruff）；
- 依赖单独一层，只改业务代码时不会重装；
- 默认 `--index-url https://pypi.tuna.tsinghua.edu.cn/simple`，可用 `--build-arg PIP_INDEX_URL=` 覆盖；
- 必须装 `tzdata`：`app/core/time.py` 用 `ZoneInfo("Asia/Shanghai")`，slim 镜像默认没有时区库，缺了会直接抛 `ZoneInfoNotFoundError`。

镜像内还需 `alembic.ini`、`migrations/`、`sql/`、`scripts/` —— 启动自动迁移和运维脚本都依赖它们，少拷一个就报错。

### 2.2 前端多阶段构建

`node:22-alpine`（`corepack enable` + `pnpm install --frozen-lockfile`，默认 npmmirror 源）→ `nginx:1.27-alpine`。

三个 Dockerfile 的构建上下文都是**仓库根目录**（`context: ..`），所以根 `.dockerignore` 负责把 `node_modules/`、`dist/`、`.venv/`、`.git/`、`.env*` 挡在上下文外：既避免 macOS 的 `node_modules` 混进 Linux 镜像（esbuild/rollup 平台二进制会不匹配），也避免 `.env` 密钥进镜像层。

### 2.3 静态站容器不反代 API

`deploy/nginx/admin.conf`、`h5.conf` 只做静态托管 + SPA 兜底，**没有** `proxy_pass /api`。接口统一由入口网关分流，好处是重启 api 不会连带静态站启动失败。

## 3. 路由规则（`deploy/nginx/default.conf`）

| location | 转发 | 要点 |
| --- | --- | --- |
| `/api/` | `http://api:8000` | `proxy_pass` **不带 URI**，保留 `/api/v1` 前缀 |
| `= /healthz` | `http://api:8000/healthz` | 健康检查，关 access_log |
| `= /api` | `return 404` | 防止漏写斜杠时落到 admin 静态站返回 200 HTML |
| `/h5/` | `http://h5:80/` | 末尾 `/` 削掉 `/h5` 前缀；h5 容器按站点根托管 |
| `= /h5` | `301 /h5/` | 少斜杠时补全，否则 Vue Router 的 base 判定会错 |
| `/` | `http://admin:80` | 管理后台 |
| `/docs`、`/openapi.json` | 默认注释 | 生产建议关闭 |

细节：

- 长缓存只写 `add_header Cache-Control "public, max-age=31536000, immutable"`；**不要同时用 `expires`**，否则响应里出现两条 `Cache-Control`。
- `client_max_body_size 10m` 与前端上传限制对齐。
- api 用 `--proxy-headers --forwarded-allow-ips '*'`，保证日志/限流拿到真实 IP。

## 4. 环境变量与安全校验

`deploy/.env` 是唯一一份部署变量（api 的业务默认值由 `apps/api/app/core/config.py` 提供，不重复抄）。

`APP_ENV=prod` 时启动会强制校验，忘改就**启动失败**而不是带弱密钥上线：

- `ALLOW_DEMO_LOGIN=false`（演示微信登录必须关）
- `AUTO_SEED=false`（业务数据不预置）
- `JWT_SECRET` ≥ 32 字节（`openssl rand -hex 32`，占位符只有 32 位，正好被拦下）

`POSTGRES_PASSWORD` 只允许 URL 安全字符（`0-9a-f`）：它是拼进 `DATABASE_URL` 的，含 `@ : /` 会把连接串截断。复用旧库就填旧密码，别按模板换新密码。

依赖注入方式：compose 里 `env_file: .env` 打底，`environment:` 覆盖并拼出 `DATABASE_URL`；`docker compose config` 可以直接看到渲染结果。

## 5. 文件存储链路

`FILE_DELIVERY=redirect` 时：上传 → api 写入 MinIO → 返回 key → 前端 `<img src="/api/v1/files/<key>">` → api 302 到 `MINIO_PUBLIC_BASE_URL/<key>`，图片流量不经过 api。

因此：

- `MINIO_PUBLIC_BASE_URL` 必须是**浏览器可达**的地址（`http://<服务器IP>:9000/<bucket>`），写成 `minio:9000` 只有容器内能解析，浏览器打不开；
- `REQUIRE_FILE_AUTH=false`，否则 `<img src>` 无法携带 token；
- 桶的匿名只读策略由 `scripts/init_minio.py` 设置（只给 `s3:GetObject`），跑过之后新上传的图才可直连。

## 6. 网络复用（为什么用 external 网络）

compose 里 `networks.backend` 声明为 `external: true, name: socialoldcare-net`：

- 已有的 `pg`、MinIO 不在本 compose 里，无法由 compose 管理，只能外部创建网络后 `docker network connect`；
- 如果让 compose 自己创建网络，再手工把旧容器接进去，compose 会因子网/label 与「它自己的网络」不一致而报 `network ... has incorrect label`；
- 别名 `postgres`、`minio` 让 `.env` 里的主机名与容器名解耦，将来换容器（比如把 `pg` 重建）只要重连一次网络，代码与配置都不动。

`pg` 容器只绑了宿主 `127.0.0.1:5432`，容器走 `host-gateway` 是访问不到的，必须走网络别名——这也是必须 `network connect` 的原因。

## 7. .gitignore 分层职责

| 文件 | 职责 |
| --- | --- |
| `.gitignore`（仓库根） | 全局红线：`.DS_Store`、`.idea/`、`*.iml`、`.env` / `.env.*`（`!.env.example` 反选保留模板）、`node_modules/`、`dist/`、`__pycache__/`、`.venv/`、`.pytest_cache/`、`.ruff_cache/`、`*.db`、`uploads/`、`*.log` |
| `apps/api/.gitignore` | 后端专属：`migrations/versions/__pycache__/`、`*.egg-info/`、`.coverage`、`htmlcov/` |
| `apps/admin/.gitignore`、`apps/h5/.gitignore` | 前端专属：`node_modules/`、`dist/`、`.vite/`、`*.local`（`VITE_BASE` / `VITE_PROXY_TARGET` 覆盖值不进仓库） |
| `apps/miniapp/.gitignore` | 小程序专属：`project.private.config.json`、`miniprogram_npm/` |
| `.dockerignore`（仓库根） | 只管构建上下文，规则比 `.gitignore` 更狠（`.git/`、`docs/`、`apps/miniapp/` 都不传） |

`dist/` 不带前导斜杠，任意层级都忽略；`.env.example` 用 `!.env.example` 反选回来，`deploy/.env.example` 同样生效。

校验方式：`git check-ignore -v <路径>`；确认已经误提交的目录：`git ls-files | grep -E 'node_modules|\.idea'`。

## 8. 上线验收（摘要）

1. `docker compose ps` 四个容器 Up，api 为 healthy；
2. `curl http://127.0.0.1/healthz` 返回 ok；
3. `curl http://127.0.0.1/api/v1/__ping` 返回 JSON `{"detail":"Not Found"}`（返回 HTML 就是路由落到静态站了）；
4. `http://120.53.13.162/` 能登录后台，`/h5/` 深链刷新不 404；
5. 后台上传图片，直链能打开；
6. `docker compose exec api alembic current` 与代码版本一致。

完整步骤、初始化命令、排障表见 [`deploy/README.md`](../deploy/README.md)。
